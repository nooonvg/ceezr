## 3. حدودُ صلاحيةِ البيئة (مثبَّتةٌ مسبقًا، `B12-V1`)

### 3.1 الفحصُ المسبق — قبلَ الحقن (60ث، البوّابةُ مطفأة)

| # | الشرط | الحدّ | الأساس |
|---|---|---|---|
| PF1 | وسيطُ 5 مِسباراتِ CPU | ≤ 447ms | المرجع × 1.10 (≈ p90 الخمول) |
| PF2 | وسيطُ 3 مِسباراتِ PG | ≤ 381ms | المرجع × 1.10 |
| PF3 | السرقة: المتوسّط / أقصى ثانية | ≤ 1.0% / ≤ 10% | المرجع 0.25% / 3.5% |
| PF4 | `system.slice` + `init.scope` | ≤ 2.0% من نواة | المرجع 0.07% (p99 1.2%) |

إخفاقُ أيِّ شرطٍ ⇒ **لا حقن**: تُحفَظُ النتيجةُ وسببُها (`preflight.json`) وتُعلَّمُ المحاولةُ
`PREFLIGHT_INVALID`، ولا تُحتسَبُ موجة.

### 3.2 أثناءَ الموجةِ وبعدَها (عيّنةٌ كلَّ ثانيةٍ من بدءِ الموجةِ حتى نهايةِ التصريف)

| IF2 | `system.slice` + `init.scope` | ≤ 5.0% من نواة |

إخفاقُ أيِّ شرطٍ هنا ⇒ الموجةُ **غيرُ صالحةٍ للتفسير** (`INVALID_ENV`): لا PASS ولا FAIL منها، والحكمُ
NOT PROVEN؛ ولا تُعادُ موجةُ القبولِ لاختيارِ أفضلِ رقم. الهوامشُ فوقَ الخمولِ تحفظُ CPU المتاحَ ضمنَ
2–5% من نواة، وهي أصغرُ من تفاوتِ P2 بينَ جولاتِ BATCH-11 المتطابقة (4–12%).

## 4. حدودُ القبولِ الأصليّة — لا تتغيّرُ مطلقًا

كما في `ACCEPTANCE-PROTOCOL.md`: G1 ≥ 99%، P2 ≤ 1,000ms، P4 ≤ 30,000ms، G4 = CLEAN، وسائرُ البوابات (G2
وG3 وG5 وG8 = 0، وG6 وG7، والهويّات، واستقرارُ البوّابة، والذروةُ = الهدف). مهلةُ 20ث، ومعدّلُ تيليجرام،
وتعريفُ السيناريو، ومزيجُ الحمل، و`gatewayRequest=5`/`gatewayDispatch=1` (الميزانيّة 21) كما هي.

## 5. الربطُ بينَ القياسات

كلُّ أثرٍ يحملُ معرّفَ الجولة (`round`): عيّناتُ المضيف (`host-sampler.py`)، و`timeline.jsonl`، وأحداثُ
المولّد، والأثرُ التشخيصيُّ للبوّابة. `orderId` يربطُ أحداثَ المولّدِ بصفوفِ القاعدة (`orders.csv`)،
وكلُّ العيّناتِ بساعةِ المضيفِ الواحدةِ بالمللي، فيُقاطَعُ الزمنُ بينَ المضيفِ والتطبيقِ والقاعدة.
