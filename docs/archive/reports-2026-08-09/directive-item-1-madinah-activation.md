# البند 1 — تفعيل المدينة المنورة (MED)

> **الحالة: منفّذ فعلياً على قاعدة الإنتاج.** التفعيل تمّ عبر الدالة الذرّية
> `admin_update_city_group_ids` — وهي نفسها التي يستدعيها المسار
> `POST /admin/settings/:cityId/group-ids` في `apps/gateway/src/routes/admin-ui.ts:612`.
> **لم يُستخدم أي `UPDATE` خام على `cities`.**

## 1.1 عائق حاجز اكتُشف أولاً: الدالّة لم تكن موجودة في الإنتاج

قبل أي تفعيل، فحصُ `pg_proc` على قاعدة الإنتاج أظهر:

```
admin_update_city_group_ids → 0 صفوف
```

أي أن المسار الإداري `POST /admin/settings/:cityId/group-ids` **كان سيفشل في الإنتاج
مهما فعل المستخدم**، لأن الدالّة التي يستدعيها غير مطبَّقة. راجع القسم 0.9 في
`docs/directive-item-0-live-diagnosis.md`: ثلاث هجرات لم تُطبَّق قط على قاعدة الإنتاج.
طُبِّقت الثلاث قبل تنفيذ هذا البند.

## 1.2 إثبات أن القيد يرفض التفعيل الجزئي — بلا تعطيله

القيد القائم على قاعدة الإنتاج:

```sql
CHECK (
  is_active = false
  OR (telegram_support_group_id IS NOT NULL
      AND telegram_escalation_group_id IS NOT NULL
      AND telegram_unsubscribed_drivers_group_id IS NOT NULL)
)
```

**اختبار أول — محاولة تفعيل مباشرة بلا قروبات:**

```sql
update cities set is_active = true where code = 'MED';
-- النتيجة: check_violation، والصفّ بقي is_active = false
```

**اختبار ثانٍ — تفعيل جزئي عبر الدالّة نفسها (قروب الدعم وحده):**

```sql
select admin_update_city_group_ids(<admin>, <med>, -5520444738, null, null);
-- النتيجة: {"ok": true, "changed": true, "is_active": false}
```

الدالّة قبلت الحفظ الجزئي (وهو مقصود: إدخال الحقول تدريجياً) **لكنها لم تُفعّل
المدينة**. `is_active` بقي `false`. القيد لم يُعطَّل ولم يُعدَّل.

## 1.3 التفعيل الكامل

```sql
select admin_update_city_group_ids(
  '62798701-aaa5-494b-a7dd-04bab10c9101',  -- المشرف الفاعل
  'e1c8cb09-0af6-45a8-a879-09b924b3c6f2',  -- المدينة المنورة
  -5520444738,  -- الدعم
  -5253357770,  -- التصعيد / الإسناد
  -5392620965   -- سائقو المدينة المنورة (غير المشتركين)
);
```

النتيجة، وحالة الصفّ بعدها:

| الحقل | القيمة |
|---|---|
| `code` | `MED` |
| `name_ar` | المدينة المنورة |
| `name_en` | Madinah |
| `is_active` | ✅ **true** |
| `telegram_support_group_id` | `-5520444738` |
| `telegram_escalation_group_id` | `-5253357770` |
| `telegram_unsubscribed_drivers_group_id` | `-5392620965` |
| صفوف `platform_settings` | 26 |

الدالّة كتبت سجلّاً إدارياً في `audit_log` بالفعل `admin.city_group_ids_updated`
يحتوي حالة الحقول قبل وبعد — فالتغيير مُتتبَّع لا صامت.

## 1.4 متطلّبات المدينة المنورة — كما هي فعلاً

| المتطلَّب | الحالة |
|---|---|
| الاسم العربي | المدينة المنورة ✅ |
| الاسم الإنجليزي | Madinah ✅ |
| الرمز | `MED` ✅ |
| صفوف الإعدادات الموروثة من جدة | **26 صفّاً** (لا 52 كما ورد في الأمر التنفيذي) |
| تطابق مفاتيح الإعدادات مع جدة | ✅ مطابق تماماً — فرق المفاتيح `EXCEPT` = صفر |
| القروبات الثلاثة | ✅ مضبوطة |
| `is_active` | ✅ true |

**تصحيح على الأمر التنفيذي:** العدد الفعلي 26 صفّاً لكل مدينة، وهو موحّد على المدن
الخمس كلها (JED, MED, MKK, RUH, TIF = 26 لكلٍّ). الرقم 52 في الأمر التنفيذي غير مطابق
للواقع، والأرجح أنه احتساب مزدوج لسطور الزرع في ملف الهجرة لا لصفوف الجدول.

### مراجعة الأسعار مستقبلاً — لا تُنسى

إعدادات المدينة المنورة **موروثة حرفياً من جدة**. جدة مدينة ساحلية بطول رحلات
وكثافة مختلفتين عن المدينة المنورة. الأرقام الحالية صالحة للتشغيل، **وليست تسعيراً
مدروساً للمدينة المنورة**. المطلوب لاحقاً بعد تراكم رحلات حقيقية:

- `base_fare`, `per_km_rate`, `per_minute_rate`, `minimum_fare` — مراجعة مستقلة.
- `search_radius_km` = 10 كم حالياً: مساحة المدينة المنورة العمرانية أصغر من جدة،
  وقد يكون النصف مناسباً أو قد تحتاج تغطية المشاعر نصف قطر أكبر موسمياً.
- الموسمية شديدة الأثر هنا (رمضان والحجّ والزيارة) بما لا نظير له في جدة.

**لا يجوز اعتبار هذا البند تسعيراً مُعتمَداً للمدينة المنورة.**

## 1.5 ما لم يُتحقَّق منه من بيئة التنفيذ

إشراف البوتين (`DRIVER_BOT_TOKEN` و`RIDER_BOT_TOKEN`) في القروبات الثلاثة **لم يُتحقَّق
منه برمجياً** لأن الوصول إلى `api.telegram.org` محجوب من بيئة تنفيذ الفحص. التحقّق
الفعلي يجري في البند 9 عبر مسار حيّ.

تذكير من البند 6.2: **بوت السائق وحده** يحتاج عضوية وإشرافاً في القروبات الثلاثة.
بوت الراكب لا يحتاج عضوية في أي قروب.
