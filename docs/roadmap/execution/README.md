# خارطة التنفيذ الحاكمة — كيف تُقرأ وكيف تُحدَّث

| [`STATUS.md`](STATUS.md) | حالة كل بند ودليله وعائقه. **المرجع الوحيد للحالة** |

## القواعد الملزمة

1. **اقرأ قبل أن تبدأ:** اقرأ `ORDER-20261012.md`، ثم `STATUS.md`، وراجع حالة البنود وأدلتها قبل اختيار المهمة التالية.
2. **نفّذ ما في الخارطة والقرارات المعتمدة**، لا افتراضاتك. إذا تعارض بند مع قرار موثق أو قيد تقني حقيقي، فتحقّق من مصدر التعارض. إذا احتاج الحسم قرارًا تجاريًا، فوثّقه في عمود «العائق» ولا تقرره نيابة عن المالك.
3. **التنفيذ وتحديث الحالة في طلب الدمج نفسه.** كل PR ينفّذ بندًا أو يغيّر حالته يحمل الشيفرة والاختبارات والوثائق وتحديث صف البند في `STATUS.md` معًا، قبل الدمج. لا يُدمج كود ثم تُحدَّث الخارطة في دفعة لاحقة.
4. **لا حالة أعلى من الدليل.** كتابة الشيفرة ليست إنجاز الميزة، ونجاح اختبار بـ mock ليس دليل سلوك حقيقي، وحالة `delivered` في outbox ليست دليل رؤية المستخدم للرسالة.
5. **لا حذف لبند ولا استبدال لمتطلب.** إذا اكتُشف متطلب جديد، أضفه صفًا جديدًا في PR المعالجة نفسه، مع سببه وأولويته وعلاقته بالبنود الأخرى.
6. **إذا تعذر إكمال بند،** فلا تضع عليه «مكتمل». سجّل ما أُنجز، وحالته الحقيقية، وسبب التوقف المحدد، ودليله، وما يلزم لتجاوزه.
7. **لا أسرار ولا بيانات حقيقية في الأدلة،** ولا عمليات مدمرة على قاعدة الإنتاج أثناء الاختبار.

## ربط كل تغيير ببند

اكتب في وصف PR سطرًا بالصيغة التالية (القالب في `.github/pull_request_template.md`):

```
بنود الخارطة: WR-18, WR-15
```

أو، لتغيير لا يمس أي بند (صيانة أو إصلاح CI مثلًا):

```
بنود الخارطة: WR-NONE: <سبب محدد لا يقل عن عشرة أحرف>
```

يفحص `scripts/check-execution-roadmap.ts` ما يلي في كل PR، ثم على `main` بعد الدمج:

- أي تغيير في `apps/` أو `packages/` أو `supabase/` أو `scripts/` أو `tests/` أو `.github/workflows/` أو `render.yaml` أو `package.json` يجب أن يُعلن بنده أو يعلن `WR-NONE` بسبب.
- كل بند مُعلن يجب أن يتغير صفه في `STATUS.md` ضمن التغيير نفسه.
- كل البنود القانونية باقية، ولا يُحذف أي منها.
- كل حالة من السلّم المعتمد.
- الحالات من `نُفذ في الشيفرة` فصاعدًا تحمل دليلًا.
- `نُشر في الإنتاج وتحقق منه` يحمل commit منشورًا.
- `اجتاز اختبار تيليجرام الفعلي` يحمل مسار دليل في `docs/evidence/`.
- `متوقف` يحمل عائقه.

## ترقية الحالة بعد النشر

التحقق الإنتاجي يأتي بطبيعته بعد الدمج والنشر. لذلك تُرفع حالة البند إلى `نُشر في الإنتاج وتحقق منه` في أقرب PR ينفّذ البند التالي، ومعها commit المنشور ورقم deploy والأثر المقيس. لا يُفتح PR توثيقي منفصل لهذا الغرض وحده. وإن لم يتبعه عمل آخر، يُرفع في PR النشر التالي.
